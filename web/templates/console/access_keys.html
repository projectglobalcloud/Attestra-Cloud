Access Keys

Credential pairs for calling the Attestra API from your own systems — pipelines that trigger verifications, custody dashboards or archival jobs. A key authenticates as this account, so it inherits exactly its permissions.

Secrets are shown once at creation and stored only as a hash. Rotate keys regularly and disable any key you no longer recognize. An account can hold up to 5 keys.

Using a key

A key acts as this account and as {{ acting_as }} — it can do what you can do here, and nothing more. Every call it makes is recorded against the same party.

1 · List what you hold. Either header form works.

curl -s {{ api_base }}/api/datasets \
  -H "Authorization: Bearer AKAT…:<secret>"

2 · Run a verification against a dataset you hold. It answers with a job id.

curl -s -X POST {{ api_base }}/api/datasets/<id>/verify-run \
  -H "X-Attestra-Key: AKAT…" -H "X-Attestra-Secret: <secret>" \
  -H "Content-Type: application/json" -d '{"c": 10}'

3 · Follow it to the result — the same steps the console shows, challenge through pairing check.

curl -s {{ api_base }}/api/jobs/<job_id> \
  -H "Authorization: Bearer AKAT…:<secret>"
